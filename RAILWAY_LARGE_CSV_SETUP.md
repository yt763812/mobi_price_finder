# Большие CSV через Telegram — Railway

## Что добавлено

- `large_csv_importer.py` — потоковый CSV (`;`, UTF-8/BOM или CP1251), колонка **«Модель»** для названия, **«Розничная цена»** для BYN. Дробная запятая поддерживается.
- В `bot.py`: выбор поставщика остаётся прежним; CSV загружается отдельно от XLS/XLSX. Защита от одновременных CSV-импортов в одном процессе.
- PostgreSQL: `COPY` в временную таблицу и атомарная замена записей только выбранного поставщика в одной транзакции. Если импорт прерывается, транзакция откатывается. Дубликаты одинаковых названий объединяются, берётся минимальная розничная цена.
- `Dockerfile.local-api`, `run_local_bot_api.sh`, `start_with_local_api.sh` — официальный Telegram Bot API и Python-бот в одном контейнере (общая файловая система). **Это отдельный Dockerfile, его нужно явно выбрать в Railway.**

## Где взять Telegram Bot API

Это **не токен от @BotFather** и не отдельная подписка. Telegram публикует исходный код сервера:

https://github.com/tdlib/telegram-bot-api

Для запуска нужны `api_id` и `api_hash` своего приложения: https://my.telegram.org/apps. Войдите с личным номером Telegram и создайте приложение (если его ещё нет). Не публикуйте `api_hash`, бот-токен и `DATABASE_URL`.

## Railway: действия

1. Сделайте резервную копию PostgreSQL перед первым боевым импортом.
2. Загрузите файлы этого архива в ваш репозиторий GitHub.
3. В настройках **существующего сервиса** Railway выберите сборку по Dockerfile `Dockerfile.local-api` (путь может задаваться через `RAILWAY_DOCKERFILE_PATH=Dockerfile.local-api`). Уберите переопределённую команду запуска, если она стоит, чтобы сработал `CMD` Dockerfile. Не запускайте два экземпляра Telegram-бота с одним токеном одновременно.
4. Добавьте переменные Railway: `TELEGRAM_API_ID` (число) и `TELEGRAM_API_HASH` (строка); **оставьте старые** `TELEGRAM_BOT_TOKEN`, `DATABASE_URL`, `OWNER_TELEGRAM_ID` и прочие настройки. В Dockerfile уже заданы `TELEGRAM_LOCAL_API_URL=http://127.0.0.1:8081`, `TELEGRAM_API_FILES_ROOT=/data/bot-api`.
5. **Перед переключением** вызовите метод Telegram `logOut` для токена вашего бота, пока старый бот остановлен. Можно открыть `https://api.telegram.org/bot<ТОКЕН>/logOut` в браузере, но токен попадёт в историю браузера; безопаснее выполнить POST через локальный терминал или Postman. `logOut` нужен один раз для перехода с облачного API на локальный. Возврат к облачному API ограничен 10 минутами. После этого запускайте новый экземпляр.
6. В Railway выделите достаточно памяти, CPU и места под Bot API, файл и временные таблицы PostgreSQL. Рекомендуется использовать отдельный **Railway volume**, смонтированный в `/data` для хранилища Bot API. Убедитесь, что в PostgreSQL хватает диска для временной таблицы и одновременной замены прайса. Объём зависит от данных и индексов, гарантировать его без теста нельзя.
7. В Telegram выберите поставщика, проверьте, что у него валюта **BYN** и корректно задан НДС, отправьте сначала маленький тестовый CSV с теми же колонками. Убедитесь в правильности поиска и цен. Затем большой прайс.

## Важные ограничения и проверки

- Пока **не проверено** на вашей Railway/PostgreSQL и реальном миллионе строк; боевой импорт требует поэтапной проверки.
- Временные PostgreSQL-таблицы и транзакция требуют пространства в БД, а Telegram Bot API сохраняет скачанные файлы на своём диске. Задайте правила очистки/ротации файлов и наблюдайте за заполнением volume. Нельзя удалять файлы во время импорта.
- Команда импорта имеет максимальный размер по умолчанию **1 ГиБ**; при необходимости менять `MAX_CSV_BYTES`.
- Обработка с parser на миллион строк может быть длительной. HTTP/Telegram обработчик импортирует в отдельном потоке, поиск при этом не блокируется полностью, но CPU и БД будут загружены.
- Импорт заменяет **весь** прайс выбранного поставщика, а не добавляет строки.
- Порог защиты от повреждённого CSV: не менее 50% строк должны иметь название и допустимую розничную цену. Стандартный файл с полным набором колонок обязателен.
- Отсутствие локального Bot API не ломает старый Excel-импорт, но большие CSV не загрузятся.
- Для стабильной работы на железе с малой RAM может понадобиться оптимизация и отдельный worker. Данные не изменяются до успешного завершения SQL-транзакции.
